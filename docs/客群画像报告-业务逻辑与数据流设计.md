> 版本：v1.0 | 日期：2026-06-01 | 状态：设计定稿

## 一、需求概述

基于预定义的标签主题，对筛选出的客群自动生成画像分析报告，支持 PC 端预览并一键导出 Word/PDF。

**核心流程**：选择标签主题 → 系统自动筛选客群 → 生成多维度分析报告 → 导出可编辑文档

| 阶段 | 输入 | 处理 | 输出 | 耗时预估 |
|------|------|------|------|----------|

#### FilterRule（筛选规则）

```python
class FilterRule(BaseModel):
    field: str       # 客户数据字段路径，如 "aum", "basic_info.occupation"
    operator: str    # ">=", "<=", "==", "in", "not_in", "between", "contains"
    value: Any       # 阈值或枚举值
    logic: str       # "AND"（默认，规则间取交集）
```

**规则示例**：
```json
[
  { "field": "aum", "operator": ">=", "value": 1000000 },
  { "field": "lifecycle", "operator": "in", "value": ["成熟期", "衰退期"] }
]
```
→ 筛选出 AUM ≥ 100万 且 生命周期为成熟期或衰退期 的客户。

### 4.2 Phase ② 客群筛选

**筛选引擎逻辑**：

```python
def segment_customers(theme: TagTheme, all_customers: list) -> list:
    """根据标签主题的 filter_rules 筛选客户"""
    result = all_customers
    for rule in theme.filter_rules:
        result = [c for c in result if _match_rule(c, rule)]
    return result

def _match_rule(customer: dict, rule: FilterRule) -> bool:
    value = _get_nested_field(customer, rule.field)
    match rule.operator:
        case ">=": return value >= rule.value
        case "<=": return value <= rule.value
        case "==": return value == rule.value
        case "in": return value in rule.value
        case "not_in": return value not in rule.value
        case "between": return rule.value[0] <= value <= rule.value[1]
        case "contains": return rule.value in value
```

### 4.3 Phase ③ 特征分析

#### 统计计算

```python
def analyze_feature(customers: list, feature: TagFeature, all_customers: list) -> FeatureResult:
    values = [_get_nested_field(c, feature.source_field) for c in customers]
    all_values = [_get_nested_field(c, feature.source_field) for c in all_customers]

    match feature.aggregation:
        case "avg":
            result_value = mean(values)
            chart_data = {"value": result_value}
        case "distribution":
            chart_data = _build_histogram(values, feature.chart_config.get("bins", 5))
        case "enum_count":
            chart_data = _count_enums(values)
        case "count":
            result_value = len([v for v in values if v]) / len(values)

    # 显著性评分
    significance = _calc_significance(values, all_values, feature.data_type)

    return FeatureResult(
        feature_id=feature.id,
        feature_name=feature.name,
        chart_type=feature.chart_type,
        chart_data=chart_data,
        significance_score=significance,
        raw_stats={"mean": mean(values), "std": stdev(values), "count": len(values)},
    )
```

#### 显著性评分算法

**设计决策**：采用 **Z-score 绝对值** 作为主要指标，辅以 **覆盖率差异** 作为补充。

**理由**：
- Z-score 直接反映"该客群的特征值偏离全行平均水平多少个标准差"，业务含义清晰
- 对于枚举型特征，使用"客群中该类别的占比 vs 全行占比"的差值
- Demo 数据量小（~100客户），不需要复杂的统计检验，Z-score 足够

```python
def _calc_significance(seg_values, all_values, data_type) -> float:
    """计算特征显著性分数（0-1，越高越显著）"""
    if data_type == "number":
        seg_mean = mean(seg_values)
        all_mean = mean(all_values)
        all_std = stdev(all_values) or 1  # 防除零
        z_score = abs(seg_mean - all_mean) / all_std
        return min(z_score / 3.0, 1.0)  # 归一化到 [0, 1]，Z=3 时满分
    elif data_type == "enum":
        seg_dist = _distribution(seg_values)
        all_dist = _distribution(all_values)
        # 最大类别占比差异
        max_diff = max(abs(seg_dist.get(k, 0) - all_dist.get(k, 0))
                       for k in set(seg_dist) | set(all_dist))
        return min(max_diff / 0.5, 1.0)  # 差异 50% 时满分
    return 0.0
```

#### Top5 筛选

```python
def select_top5(all_results: list[FeatureResult]) -> list[FeatureResult]:
    """从 is_top5_candidate=True 的特征中选显著性最高的 5 个"""
    candidates = [r for r in all_results if r.is_top5_candidate]
    candidates.sort(key=lambda r: r.significance_score, reverse=True)
    return candidates[:5]
```

### 4.4 Phase ④ 相关性洞察

#### 交叉统计引擎

**设计决策**：采用 **Lift（提升度）** 作为关联强度指标，阈值为 **lift ≥ 1.3 且 support ≥ 3%**。

**理由**：
- Demo 客群样本小（20-50人），lift > 1.5 + support > 5% 会导致规则过少
- lift ≥ 1.3 表示"A 出现时 B 的概率比随机高 30%"，已有业务价值
- support ≥ 3% 确保规则至少在 1-2 个客户上成立，避免噪声
- 过滤掉"显而易见"的关联（如 asset_level == "高净值" → aum > 100万），只保留非平凡规则

```python
def discover_correlations(customers: list, features: list[TagFeature]) -> list[CorrelationRule]:
    """发现客群内标签特征间的非平凡关联"""
    rules = []

    # 选取枚举型特征做交叉分析
    enum_features = [f for f in features if f.data_type == "enum"]

    for f1, f2 in combinations(enum_features, 2):
        vals1 = [_get_nested_field(c, f1.source_field) for c in customers]
        vals2 = [_get_nested_field(c, f2.source_field) for c in customers]

        for v1 in set(vals1):
            for v2 in set(vals2):
                # 计算 support 和 lift
                count_a = sum(1 for v in vals1 if v == v1)
                count_b = sum(1 for v in vals2 if v == v2)
                count_ab = sum(1 for a, b in zip(vals1, vals2) if a == v1 and b == v2)
                n = len(customers)

                support = count_ab / n
                lift = (count_ab / n) / ((count_a / n) * (count_b / n)) if count_a and count_b else 0

                if lift >= 1.3 and support >= 0.03:
                    rules.append(CorrelationRule(
                        antecedent=f"{f1.name}={v1}",
                        consequent=f"{f2.name}={v2}",
                        support=support,
                        lift=lift,
                        confidence=count_ab / count_a if count_a else 0,
                    ))

    # 过滤 trivial 关联
    rules = [r for r in rules if not _is_trivial(r)]
    # 按 lift 降序，取 Top5
    rules.sort(key=lambda r: r.lift, reverse=True)
    return rules[:5]

def _is_trivial(rule: CorrelationRule) -> bool:
    """判断是否为显而易见的关联"""
    trivial_pairs = [
        ("资产等级", "AUM"),       # 资产等级高 → AUM 高，定义性关联
        ("生命周期", "流失概率"),   # 流失预警 → 流失概率高，同义反复
    ]
    for a, b in trivial_pairs:
        if (a in rule.antecedent and b in rule.consequent) or \
           (b in rule.antecedent and a in rule.consequent):
            return True
    return False
```

### 4.5 Phase ⑤ 报告生成

#### 报告结构体组装

```python
async def generate_report(theme: TagTheme, user: str) -> ReportInstance:
    """完整的报告生成流程"""
    all_customers = get_personal_customers()

    # Phase ② 客群筛选
    seg_customers = segment_customers(theme, all_customers)
    overview = generate_overview(seg_customers)

    # Phase ③ 特征分析（按标签组分组）
    feature_groups = []
    for group in theme.tag_groups:
        results = []
        for fid in group.feature_ids:
            feature = get_feature_definition(fid)
            result = analyze_feature(seg_customers, feature, all_customers)
            result.llm_insight = await generate_feature_insight(theme, group, feature, result)
            results.append(result)
        top5 = select_top5(results)
        feature_groups.append(FeatureGroup(
            group_id=group.id,
            group_name=group.name,
            features=results,
            top5_features=top5,
        ))

    # Phase ④ 相关性洞察
    all_features = [f for g in feature_groups for f in g.features]
    correlations = discover_correlations(seg_customers, get_feature_definitions())
    for corr in correlations:
        corr.llm_insight = await generate_correlation_insight(theme, corr)

    # Phase ⑤ LLM 生成营销建议
    recommendations = await generate_recommendations(theme, seg_customers, feature_groups, correlations)

    # 组装报告
    report = ReportInstance(
        id=generate_report_id(),
        theme_id=theme.id,
        theme_name=theme.name,
        generated_at=now(),
        generated_by=user,
        data_date=today(),
        customer_count=len(seg_customers),
        status="completed",
        summary=ReportSummary(...),
        overview=overview,
        feature_analysis=feature_groups,
        correlation_insights=correlations,
        recommendations=recommendations,
    )

    save_report(report)
    return report
```

### 4.6 Phase ⑥ 导出

#### 设计决策：前端 canvas 转图片 + 后端模板组装

**理由**：
- ECharts 图表已在前端渲染，直接 canvas 转 base64 图片，保真度最高
- 避免后端用 matplotlib 重绘图表的开发成本和样式不一致问题
- Word 用 python-docx 模板填充，PDF 用 HTML 模板 + Playwright 截图

**Word 导出流程**：
```
前端 ECharts → canvas.toDataURL() → base64 图片数组
        │
        ▼
POST /api/report/{id}/export/word
body: { chart_images: { "avg_aum": "data:image/png;base64,...", ... } }
        │
        ▼
后端 python-docx:
  1. 读取 docx 模板（预定义的报告样式骨架）
  2. 填充文字内容（摘要、统计、LLM 文案）
  3. 插入图表图片
  4. 设置页眉页脚（报告名称 + 页码）
  5. 返回文件流
```

**PDF 导出流程**：
```
前端 ECharts → canvas.toDataURL() → base64 图片数组
        │
        ▼
POST /api/report/{id}/export/pdf
body: { chart_images: { ... } }
        │
        ▼
后端:
  1. 用 Jinja2 渲染 HTML 报告模板
  2. 内嵌 base64 图片（无需文件IO）
  3. Playwright 打开 HTML → 生成 PDF
  4. 返回文件流
```

## 七、技术选型决策

### 7.1 显著性评分：Z-score 绝对值

**选型理由**：
- 业务含义直观：Z=1 表示偏离均值 1 个标准差，Z=2 表示显著偏离
- 计算简单，适合 Demo 数据量（100 客户）
- 归一化到 [0,1] 后可直接用于排序
- 对于枚举型特征，用"占比差值"替代，语义一致

**备选方案（已排除）**：
- 卡方检验：样本量太小，p 值不可靠
- 信息增益：需要决策树结构，过重
- 变异系数（CV）：只反映离散度，不反映"与全行的差异"

### 7.2 关联规则阈值：lift ≥ 1.3, support ≥ 3%

**选型理由**：
- Demo 客群 20-50 人，3% support = 至少 1 人，是最低有效阈值
- lift ≥ 1.3 过滤掉弱关联，保留有业务价值的规则
- 配合 trivial 过滤器（排除定义性关联），确保输出的规则有"意外发现"价值

**备选方案（已排除）**：
- lift > 1.5 + support > 5%：阈值过严，小客群可能 0 条规则
- 皮尔逊相关系数：只适用于连续变量，不适用枚举交叉

### 7.3 报告模板：单模板 + 可配置 sections

**选型理由**：
- 需求明确是单主题报告，不需要多套模板切换
- 通过 TagGroup 配置控制报告的第 3 章有哪些分析维度，灵活性足够
- 模板用 Python 类 + Jinja2 模板，Word 用 python-docx，PDF 用 HTML+Playwright
- 后续扩展多模板时，只需新增模板类，不影响数据层

### 7.4 图表嵌入：前端 canvas 转 base64

**选型理由**：
- ECharts 已在前端渲染，样式完全一致
- canvas.toDataURL() 零额外开发成本
- base64 直接嵌入文档，无需图片文件 IO
- 用户预览和导出看到的图表完全一致

**备选方案（已排除）**：
- 后端 matplotlib 重绘：需要维护两套图表代码，样式难对齐
- 后端 ECharts (Node.js)：需要额外的 Node 服务，架构变重
- 前端 puppeteer 截图：需要 headless 浏览器，不如 Playwright 成熟
